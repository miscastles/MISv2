====================================================================================
CHANGES
====================================================================================

1. Report Modules

	- Added Service Type (Request ID prefix) filter to the following reports:
	  53 - Service Installation & Reprogramming Report
	  54 - Service Maintenance Report
	  55 - Service Pullout Report

		Filter options:
		[NOT SPECIFIED]   = No filter (previous behavior)
		ALL AUTOGENERATED = HD + SD prefixed Request IDs only
		HD                = Helpdesk-generated Request IDs only
		SD                = No Request ID (system-generated) Request IDs only

	- Filter applies to the report preview and to all exported Excel sheets
	  (Daily, Detail and Summary).

	- Added Service Type combo box in frmPrintOptionCriteria.cs.

	- Service Type value is passed to the report search value for reports
	  53, 54 and 55 (preview and export).

2. Database ( MCC )

	- Updated spViewReport -> "Service Attempt" block.
	  (Report preview / Daily sheet)
		- Added Service Type parameter (parameter 10).
		- Added @serviceTagClause (Request ID / IRNo prefix filter) appended
		  to the main WHERE clause.

	- Updated spViewReport -> "Detail Service Attempt" block.
	  (Detail sheet / Summary sheet)
		- Added Service Type parameter (parameter 11).
		- Added @serviceTagClause (Request ID / IRNo prefix filter) appended
		  to the main WHERE clause.
		- Filter also applies to the tmplatestservice repository table used
		  by the Summary sheet sections.

	- When the Service Type parameter is not passed or is [NOT SPECIFIED],
	  no filter is applied (backward compatible with existing callers).

	- spProcessReportDataStorage not changed. CURRENT SLA % is computed from
	  the filtered Summary sections.

	- Stored procedure must be recreated using its original sql_mode
	  (without ONLY_FULL_GROUP_BY).
